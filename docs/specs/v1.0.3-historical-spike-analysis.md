## 1. Problem Statement

### Current State
- Spike detection only evaluates the **latest data point** against a 30-minute moving average window
- Users can only see **real-time spikes** - no historical analysis capability
- No way to answer questions like "How many spikes occurred yesterday?" or "When did payment-service spike?"

### User Need
- Analyze spike events over historical time ranges (last 24h, 7d, custom)
- Identify spike patterns and trends
- Correlate spikes with deployments or traffic events
- Generate reports for capacity planning

### Proposed Solution
- Implement retrospective spike analysis using **Go-side calculation**
- Allow users to specify time range (start/end) and moving window size
- Analyze ALL replicasets in the namespace
- Return all spike events found in the time range

## 3. Algorithm Specification

### 3.1 Go-Side Historical Spike Detection

**Core Approach:**
- Fetch historical metrics from Prometheus for the time range
- Process data point by point in Go (not PromQL)
- Reuse existing `SpikeDetector` logic where possible

### 3.2 Processing Flow

```
1. Parse Request
   ├── start_time, end_time from query params
   ├── window_size (5m/15m/30m/1h)
   ├── threshold (default 50%)
   └── filters (namespace, replicaset)

2. Fetch Historical Data
   ├── Call Prometheus QueryRange for CPU
   ├── Call Prometheus QueryRange for RAM
   └── Return: []TimelineMetric with all data points

3. Group by Replicaset
   ├── Extract replicaset name from pod (remove -xxxx suffix)
   └── Group metrics by namespace/replicaset

4. For Each Replicaset:
   ├── Sort data points by timestamp (ascending)
   ├── For each data point i:
   │   ├── Calculate moving average from points [0..i-1] with window size
   │   ├── Compare current vs moving average
   │   ├── If deviation > threshold: RECORD SPIKE
   │   └── Apply cooldown (skip spikes within 15min of last)
   └── Collect all spikes

5. Aggregate Results
   ├── Count spikes by type (CPU/RAM/both)
   ├── Rank replicasets by spike count
   └── Prepare response with pagination
```

### 3.3 Moving Average Calculation

**Formula:**
```
MovingAverage(i) = Sum(points from window_start to i-1) / Count(points)

Where:
- window_start = max(0, i - window_size_in_points)
- window_size_in_points = window_minutes / data_interval_minutes

Example (30min window, 30sec intervals):
- For point at T+30min: window = 60 points (30min / 30sec)
- Moving average = sum of last 60 points / 60
```

### 3.4 Spike Detection Logic

**For each data point:**
```go
func detectSpike(current, movingAvg, threshold float64) (bool, float64) {
    if movingAvg <= 0 {
        return false, 0
    }
    
    deviation := (current - movingAvg) / movingAvg * 100
    
    if deviation > threshold {
        return true, deviation
    }
    
    return false, deviation
}
```

**Cooldown Logic:**
- After detecting a spike, skip detections for the same container within 15 minutes
- This prevents duplicate spike events for sustained high usage

### 3.5 Severity Classification

| Deviation % | Severity | Color |
|-------------|----------|-------|
| 0-50% | normal | green |
| 50-100% | low | yellow |
| 100-200% | medium | orange |
| 200%+ | critical | red |

function buildAnalyzeQuery(params: AnalyzeParams): string {
  const queryParams = new URLSearchParams();
  
  if (params.start) queryParams.set('start', params.start);
  if (params.end) queryParams.set('end', params.end);

## 6. Performance Considerations

### 6.1 Data Volume

| Time Range | Data Points (est.) | Memory (est.) |
|------------|-------------------|---------------|
| 24 hours | 2,880 per pod | ~500KB per pod |
| 7 days | 20,160 per pod | ~3.5MB per pod |
| 30 days | 86,400 per pod | ~15MB per pod |

### 6.2 Optimization Strategies

1. **Sampling:** For large ranges, increase step size
   - 24h: 30sec step (2880 points)
   - 7d: 5min step (2016 points)
   - 30d: 15min step (2880 points)

2. **Parallel Processing:** Process replicasets concurrently
   ```go
   results := make(chan HistoricalSpike)
   var wg sync.WaitGroup
   
   for replicaset := range replicasets {
       wg.Add(1)
       go func(rs string) {
           defer wg.Done()
           spikes := analyzeReplicaset(rs, metrics, config)
           for _, spike := range spikes {
               results <- spike
           }
       }(replicaset)
   }
   ```

3. **Result Limiting:** Cap at 1000 spikes per request
   - Return top spikes by deviation percentage
   - Provide pagination for more

### 6.3 API Timeout
- Default timeout: 60 seconds
- For large ranges, return partial results with warning

## 14. Appendix

### A. Time Parsing

Support both absolute and relative times:

```go
func ParseTime(input string) (time.Time, error) {
    // Relative: 24h, 7d, 30d
    if strings.HasSuffix(input, "h") || strings.HasSuffix(input, "d") {
        return parseRelative(input)
    }
    // Absolute: RFC3339
    return time.Parse(time.RFC3339, input)
}

func parseRelative(input string) (time.Time, error) {
    duration, err := model.ParseDuration(input)
    if err != nil {
        return time.Time{}, err
    }
    return time.Now().Add(-duration), nil
}
```

### B. Sample Calculations

**Example: 30-minute window with 30-second intervals**

```
Time series data points (T0 to T60):
T0:  10%  ─┐
T1:  12%  │
T2:  11%  │
...  ...  │  Moving window (last 60 points)
T58: 45%  │  = sum(10+12+11+...+40) / 60
T59: 40%  │  = 1800 / 60 = 30%
T60: 50% ─┘
           │
           ↓ Spike detection at T60:
           Deviation = (50 - 30) / 30 × 100 = 66.7%
           Since 66.7% > 50% threshold → SPIKE!
```
